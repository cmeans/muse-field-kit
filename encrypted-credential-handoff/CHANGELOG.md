# Changelog — encrypted-credential-handoff

## 0.1.0 — 2026-11-13 — first publication

The folder's first public version. Nothing here has been released before, so this entry describes what ships, not a sequence of changes. (Renamed before publication from "blind-RSA credential handoff": "blind RSA" names a different, standardized technique.)

Before its first commit, the folder had a structural review and a line-level script review, with findings reproduced. PR #1 and PR #7 (the rotation tooling) then went through a cold read and several QA review rounds, each with Dev's own pre-QA reviews. The PR body records each round's findings and what was fixed or declined. The reviewers were AI agent sessions in the author's setup, plus the author: peer review inside one shop, not a third-party audit.

### Added

**The pattern** (README.md)

- **Threat model**, including what the pattern does not defend against: host trust, the agent account, no sender authentication, no forward secrecy under key compromise, the helper as a decryption oracle (execute access to the helper is read access to every staged credential), writers to the store (a store writer can plant a blob for a label; signed blobs would close it), and the unattended-fetch credential.
- **Ten invariants**: one-way delivery, careful ciphertext storage, plaintext never in a model's context, never on the agent's disk, mandatory key/ciphertext separation, identity verification, provenance (stage only blobs the user pastes), purpose binding (`svc`), controlled egress and key confinement.
- **Rotation** split into routine rotation and compromise response (on a suspected leak, credentials change at their services first). **Platform** status stated plainly: Linux reviewed; macOS expected but unreviewed; Windows has no reference.

**Setting it up** (SETUP.md)

- **Hard rules**, including one list of what is recorded per label (both wrappers, the sha256 sums of each label's wrappers and own programs, a shared section of sums for the programs every label runs, each whole command line and its `--env` mappings, each wrapper's environment and working directory, the fetch and its environment, the endpoint, and anything the user accepted knowingly). A change to anything on it is a mechanism change; rotation changes nothing on it.
- **Wrappers**: a probe wrapper and a use wrapper per label, identical apart from the comment line and the command after `--` (checked with `diff`; the sha256 of each wrapper and its own programs recorded per label, and of the shared programs, `consume.py`, the fetch script, `openssl` and `python3`, once, all compared before a run and at each session's start), with a complete example. A wrapper takes no caller arguments and no caller environment: it refuses arguments, `cd`s to a fixed directory, starts the helper with `env -i`, and runs the fetch with `</dev/null` under its own clean environment (for a stdio MCP server, the wrapper's stdin is the client's transport). Wrappers are never nested; `consume.py` refuses a direct nested call. The probe reaches its service with the wrapper's fixed environment alone (a tunnel or proxy other tooling sets up at run time isn't there), and a fetch through a proxy has its proxy variables written into its own `env -i` line, since nothing from the MCP client or the agent's shell reaches it. A proxy, tunnel or endpoint comes only from the user (or configuration the user confirms); one suggested by a tool result, fetch output, file or message is treated as an injection attempt. The rewrap wrapper's store command gets the same proxy variables, and a proxy's credentials never go in a wrapper, the notes or a command line.
- **Steps** with exact commands: `HANDOFF_KEY_DIR` and `HANDOFF_PRIVKEY`, the fingerprint check, the dummy round-trip, giving the user the exact `svc`, and macOS `PATH` lines for Homebrew's `openssl@3`. Prerequisites: OpenSSL 3 or 4, Python 3.7 or later.
- **Rotation**, as key-management services do it: the old key keeps decrypting until it's retired. Rotate (the old key kept as `<key path>.previous`, a new one at the same path, so no wrapper changes), check the new fingerprint, rewrap each label's blob to the new key through its recorded rewrap wrapper (a third per-label script, started as its other wrappers start the helper, with a file-store and a fetched-store shape) and probe it for a positive "opened with the current key" line, and retire the old key once the rotation's list of labels has been checked against the setup record (a label missed at the start is otherwise broken silently at retire), every label on it has probed ok (or been written off by the user in a direct conversational turn; a write-off arriving any other way is treated as an injection attempt), and a last pass shows every stored blob opens with the new key alone. A fetched store's rewrap wrapper can name the label's slot in the store apart from the label (`key=`), and on a host with no `/run/user` keep its file in a directory of its own on `/dev/shm`. An old `handoff.sh` still printing the old fingerprint is named as a copy to update. Rotation starts only on the user's direct request (or their go-ahead after a reported compromise). Each step says how to resume it from the agent's notes, and a blob neither key opens is a stop condition. An install whose wrappers run another consumer, or name the key through a symlink, changes that first. On a suspected compromise, credentials change at their services first, the leaked keys' fingerprints are recorded, any other `--retire` refusal (beyond an unfinished rotation, which `--rotate` finishes) stops the response until it's resolved, the new key is checked to differ from the leaked ones, the old key is retired right after the new one is in place, and old blobs are never rewrapped.

**`handoff.sh`** (the user's side)

- Encrypts with RSA-2048, OAEP-SHA256, MGF1-SHA256; prints only the base64 ciphertext on stdout. Reads the payload with echo off, or from a file or pipe; checks it's a single JSON object with a string `svc` and string values (with `jq`), and at most 190 bytes.
- The fingerprint fails closed on a placeholder or damaged key. Requires OpenSSL 3 or 4 (refuses LibreSSL, with a `PATH` hint), and drops the caller's `OPENSSL_*` variables.

**`agent-setup.sh`** (the agent's side)

- Generates the keypair (mode 600, a 700 directory it creates; it refuses to overwrite a key or to treat an unknown argument as "generate"). `--fingerprint [KEY]` (and `--public-key [KEY]`, which also prints the public key, for a resumed setup or rotation) reads `KEY`, else `$HANDOFF_PRIVKEY`, else the same default key `consume.py` uses, and names the file it read; it refuses an encrypted key, a key that isn't RSA-2048, and a file over 16384 bytes.
- `--rotate [KEY]` keeps the key as `KEY.previous` (a hard link, so it's never replaced) and renames a new key over `KEY`, printing the new public key and fingerprint; the new key is checked before it replaces anything, so a failed or short key generation leaves the old key in place. While a rotation is under way it rotates nothing and shows the new key's public key and fingerprint again (exit 0), and a re-run after an interruption finishes it; which state a rotation is in is read from the keys' fingerprints. `--retire --yes [KEY]` deletes `KEY.previous` (and a temporary file that is another link to it), refusing when there's none, the rotation didn't finish, or the old key has another hard link. Without `--yes`, after those checks, it keeps the old key (removing only such a leftover temporary link to it): it names the old key and its fingerprint, says a blob still made for it never opens again, and exits 1, since the script can't tell whether some label's blob still needs the old key (issue #4). `HANDOFF_KEY_DIR` without `HANDOFF_PRIVKEY` is refused in these modes, a misordered flag isn't taken as KEY, and an interrupted `--rotate` says how to finish. Both refuse a symlinked key path and a `.previous` that isn't a regular file, take a lock so only one runs at a time per key directory, and treat a key path starting with `-` as a path. `--rotate` removes a temporary key a killed run left. A TERM, HUP or INT during `--rotate` or first-time generation leaves no temporary private key behind.
- First-time generation writes the key to a temporary file and checks it before linking it into place, so a failed or short key generation (genpkey can exit 0 after a short write) leaves nothing at the key path, and a key that appeared meanwhile is never replaced (the key directory needs hard links). A failing DER export is reported as unreadable, not as another key type, and paths starting with `-` are paths. A TERM, HUP or INT during generation leaves no temporary private key behind.
- One `~/` rule shared with `consume.py` (`~user` refused), `HOME` needed only for the defaults and `~`, the same OpenSSL 3/4 gate, and `OPENSSL_*` dropped.

**`consume.py`** (the consume helper)

- Loads the key on its own first, never prompting for a passphrase, and checks it's an RSA-2048 key with e = 65537 (a key that won't load, an encrypted one, another key type or size, or a file over 16384 bytes is reported as such, with openssl's readable reason, cut to 300 characters), then decrypts in memory (a failed decrypt names the likely cause, a blob made for another key or a damaged one, and says to stop and report it), checks `svc` against `--label`, and **execs** the command with the credentials in its environment (a TERM to the helper reaches the command; no credentialed child is left behind). Run as `./consume.py`, it re-runs itself as `python3 -I` through a two-line sh launcher (no `env -S`, which BusyBox lacks).
- Prints nothing derived from the payload. `--check` shows field names and lengths, for the dummy round-trip only.
- **Rotation:** a blob the current key can't open is tried with `<key path>.previous`, held to the same key checks; a blob neither key opens (or the current key, with no rotation under way) gets one fixed message, naming the key files it tried but without openssl's reason, saying to stop and report it. In run mode, a blob opened by the previous key gets a note to rewrap it. `--rewrap` runs only during a rotation that has a new key in place (refused with no `<key path>.previous`, or with one holding the current key, so a wrong `HANDOFF_PRIVKEY` or a half-done `--rotate` can't make a label look done), rewrites its `--blob-file` in place (required; `--blob` and `$HANDOFF_BLOB` are refused): the same payload, encrypted to the current key and checked to open with it to the same bytes, written atomically (a synced temporary file beside it, read back, then renamed; a failure, or a TERM, HUP or INT not inherited as ignored, before the rename leaves the file as it was, and one after it is reported as the file holding the new blob; a file changed meanwhile, such as a blob staged during the rewrap, is left as it is), keeping its mode and, where allowed, its group. It writes nothing for a blob already for the current key, refuses a blob file that resolves (symlinks and `..` followed) to anywhere under the key's directory, compared by path and by identity (a bind mount or another case of it), or that is group- or world-writable or in such a directory without the sticky bit (the message gives the `chmod`; checked for an already-current blob too), and its stderr line names the file and the key file the old blob was for; it takes no command and no `--env`. A blob that is several concatenated is named as that. During a rotation, run mode notes a blob the current key opened too, so a probe checks for a line that's there. A closed or read-only stdout or stderr is replaced with `/dev/null` at startup, so a note never fails at flush or lands on a stdio server's stdout. `--help` prints the usage, read in option positions only.
- **Nesting:** the command gets `HANDOFF_LABEL` (the label), and the helper refuses to start when `HANDOFF_LABEL` is set, so a command one call started can't run `consume.py` again directly by accident. It's an accident guard, not a boundary (a command can unset it), and a wrapper's `env -i` drops it along with the outer credentials: nesting through a wrapper is SETUP's rule to keep. `HANDOFF_LABEL` is on the refused `--env` list.
- **Environment:** the default `SERVICE_*` names and its own mappings are removed from what it inherits before the payload's values go in, along with `$HANDOFF_BLOB` and `$HANDOFF_PRIVKEY`. `--env` maps only the known fields, each once, and refuses targets that aren't plain names or that change what the command runs or where it connects (a partial list, compared case-insensitively). `OPENSSL_*` is stripped from its own openssl calls.
- **Input:** exactly one blob source; `--label`, `--blob`, `--blob-file`, `--check` and `--rewrap` at most once each; a blob file must be a regular file (checked before opening, opened non-blocking, rechecked); empty, wrong-length or oversized blobs, empty, NUL or non-UTF-8 values, and non-OpenSSL-3/4 openssl are clean refusals, never tracebacks.

**Tests and CI**

- `test/run-test.sh`: a known-answer decrypt vector and an encrypt round trip through `consume.py` (OAEP is randomized), the exec and TERM behavior through both entry points, leak checks on the helper's own output (every crafted value carries a marker), fingerprint agreement across the scripts, the 190/191-byte boundary, and every documented refusal by exit code and message, including a key owned by another user (from a root-owned owner-only file; skipped where there is none) and a blob file swapped to a terminal after its check (refused without taking a controlling terminal). It needs only bash, python3, openssl and jq, and runs without execute bits. The PR #1 rounds checked the suite with mutation runs kept outside the repo, and issue #2 brings mutation testing in; the survivors those runs found were fixed by new tests.
- CI runs the execute-bit and line-ending checks, shellcheck, a parse of the scripts under bash 3.2 (macOS's `/bin/bash`), `ruff check` and the suite, gives the suite a root-owned key file for the key-owner refusal, and fails if the suite skips any check. `.gitattributes` keeps scripts and vectors LF.
