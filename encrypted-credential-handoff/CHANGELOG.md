# Changelog — encrypted-credential-handoff

## Unreleased — QA round 6 revision (2026-11-11)

QA's round 6 on PR #1 (1 Medium, 7 Low, 2 Nit). Fixed:

- **Wrappers pass no caller arguments (the Medium).** Round 5's SETUP line told wrappers to pass `"$@"` after `--`, to the command, and a caller's arguments there can change the tool's endpoint or make it print its config, against the recorded-command rule. SETUP step 7 now says a wrapper's whole command line is fixed and recorded, with no `"$@"` anywhere, and gives a complete wrapper script and its MCP `command` stanza. The `consume.py` docstring and comments call the once-only options a backstop for a wrong wrapper, not a supported shape.
- **macOS instructions you can follow:** SETUP gives the exact `PATH` lines for the agent's shell, the user's shell and a wrapper (Homebrew's `openssl@3`, Apple Silicon and Intel paths), under the Platform rule's "if the user chooses to proceed". The OpenSSL refusal in all three scripts names the fix.
- **A working clean-environment recipe** for an inner wrapper (`env -i PATH=… HANDOFF_PRIVKEY=… HANDOFF_BLOB=… /abs/path/consume.py …`).
- **`./consume.py`** in SETUP's commands (a bare `consume.py` isn't on `PATH`).
- **Blob files are checked before they're opened:** a device (a tty can become the controlling terminal on open) or an empty path is refused first, and the open adds `O_NOCTTY`.
- **`on-unlabel`** reads the head and the labels in two calls, so a missing head can't be mis-split.
- **Counts:** 74 refusal checks plus one over 107 `--env` targets. Of 97 mutants (against a passing baseline), 94 are killed. The 3 survivors are the blob-file layers that only matter in a race or for a device's side effects on open, which no test here can observe: the `fstat` re-check after the pre-open `stat`, `O_NONBLOCK`, and the pre-open `stat` itself (the `fstat` still refuses without it).
- **Narrowed claims:** the Python version check helps only on 3.6 (older versions fail to compile the file first), and isn't tested, having no 3.6 to run on; `|| exit 127` on the launcher line is a backstop, since `sh` already exits 127 when `exec` fails.

## Unreleased — QA round 5 revision (2026-11-11)

QA's round 5 on PR #1 (13 Low, 2 Nit, mostly from a cross-platform pass). Fixed:

- **The launcher:** `exec python3 -I "$0" "$@" || exit 127` (a backstop: `sh` already exits 127 when `exec` fails), and test 2b now runs through the launcher too (`sh consume.py`), checking the command takes the helper's PID. `.gitattributes` keeps the scripts and vectors LF (a CRLF checkout broke the launcher and put `\r` on the last argument), and CI fails on a CR in them.
- **Blob files:** opened non-blocking, so a FIFO with no writer is refused instead of hanging; pipes, FIFOs and process substitutions are refused (use `--blob` or `$HANDOFF_BLOB`), as the docstring now says.
- **Wording that was broader than the code:** the helper removes the default names and its own mappings from the inherited environment, not an outer wrapper's mappings under other names. The docstring and SETUP say so, and SETUP adds that a wrapper passes `"$@"` only after `--`, and that wrappers shouldn't nest.
- **More `--env` names refused:** `HOSTALIASES`, `CURL_HOME`, `WGETRC`, `DOCKER_HOST`, `KUBECONFIG`, `XDG_CONFIG_HOME`, and the `NPM_CONFIG_` and `PIP_` prefixes. The test now checks every listed name in both cases and every prefix, from its own copy of the list.
- **Tests:** the leak marker is now in every crafted value (`1d`, the 190/191-byte payloads, `handoff.sh`'s refusal inputs); `handoff.sh`'s OpenSSL gate is tested with a fake LibreSSL, for `--fingerprint` and for encrypting; the ERR trap reports a failure once.
- **Counts:** 72 refusal checks plus one over 107 `--env` targets; a mutation run of 95 mutants (QA's round-5 survivors and a formatter's rewrite of the launcher line included), checked against a passing unmutated suite first, kills all 95. macOS portability of the test itself is issue #3.
- **Smaller:** `check_openssl` decodes openssl's output with `errors="replace"`; Python 3.6 gets a message, not a traceback (untested; older versions fail to compile first); `on-unlabel` re-reads the head and doesn't promote for a commit that's no longer the head; SETUP notes macOS's LibreSSL and a GUI client's minimal `PATH`.

## Unreleased — QA round 4 revision (2026-11-11)

QA's round 4 on PR #1 (1 Medium, 16 Low, 2 Nit). Fixed:

- **No inherited default or mapped credential name reaches the command.** The command saw an inherited `SERVICE_USERNAME` beside `--env username=APP_U`, so a nested wrapper's parent could hand service A's credential to service B, and the round-3 test required it. Now every default name and every mapped name is removed from the inherited environment before the payload's values go in, and so is `$HANDOFF_PRIVKEY` (only `$HANDOFF_BLOB` was).
- **More `--env` targets refused**, compared case-insensitively: `OPENSSL_*` (which load code), the proxy variables (`HTTPS_PROXY`, `https_proxy`, `ALL_PROXY` and others) and CA-bundle variables (`SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE`, `NODE_EXTRA_CA_CERTS` and others), which would let the payload's writer choose where the credential goes, and `CLASSPATH`, `PERLLIB`, `PROMPT_COMMAND`, `SSH_ASKPASS`. The list is still partial; the recorded-command rule is still the control.
- **`consume.py` input checks:** exactly one blob source, `--label`, `--blob`, `--blob-file` and `--check` at most once each (a wrapper's caller can't relabel it), an empty or wrong-length blob refused before openssl runs, a blob file capped at 8192 characters, an empty credential value refused, and the same OpenSSL 3/4 gate as `handoff.sh`. Run as `./consume.py`, it re-runs itself as `python3 -I` (a two-line sh launcher at the top of the file, not `env -S`, which BusyBox lacks), so the caller's `PYTHON*` variables don't reach the helper itself; a wrapper that calls Python directly should use `python3 -I` too. `agent-setup.sh` has the same OpenSSL gate now, and needs `HOME` only for the default paths and a leading `~`. A blob file may start with a byte-order mark, must be a regular file (`--blob-file /dev/stdin` would take the command's stdin), and an unreadable one says why; a failing `openssl version` shows openssl's reason. `handoff.sh`'s gate message now says "OpenSSL 3 or 4" like the others, and SETUP's prerequisites say OpenSSL 3 or 4 and Python 3.7 or later.
- **The command starts with SIGPIPE and SIGXFSZ at their defaults.** Python ignores both at startup, and an ignored signal survives exec, so `yes | head -1` under the helper failed with "Broken pipe".
- **One `~` rule for both scripts:** a leading `~/` is expanded in `HANDOFF_PRIVKEY`, `HANDOFF_KEY_DIR` and `--blob-file`, and `~user` is refused (`consume.py` read `~root/k.pem` as `/root/k.pem`, `agent-setup.sh` as `$HOME/root/k.pem`). The default key path is defined once per script (in `agent-setup.sh`, the "non-default location" check uses it too, with `HOME` normalized). `agent-setup.sh` says so when `HOME` is unset, instead of dying on an unbound variable.
- **Tests:** an ERR trap names the line when a command substitution fails. Every crafted payload value carries a marker that the leak check looks for (round 3's "no dummy value appears" checked only the vector's two values, and three echo mutants survived). New refusals cover no `svc`, not JSON, not an object, a non-string value, `--env` without `=`, an unrecognized argument, no blob, a missing option value and the new checks above: 85 refusal checks, and a mutation run of 84 mutants (QA's three survivors included), checked against a passing unmutated suite first, kills all 84.
- **Workflows:** removing `Dev Active` no longer promotes beside `QA Active`, `QA Failed`, `Ready for QA Signoff` or `QA Approved`; QA Gate fails on an API error instead of exiting green; `on-label` reads the labels live; `pr-labels-ci.yml` re-checks the head before editing; the headers say what fork PRs get; `ci.yml` and `qa-gate.yml` note that their names are required checks.
- **Wording:** `SETUP.md`'s not-a-mechanism-change list no longer says "adjusting a label"; `--check`'s docstring mentions the svc line; a test comment matches its check; the dead `except ValueError` around the exec is gone.

## Unreleased — round-3 (QA cold review) revision (2026-11-11)

Produced by a QA review of PR #1 at its round-2 head, from eight reviewer perspectives, with findings reproduced against throwaway keys. These are the fixes for its must-fix-before-merge items.

- **Scripts are executable in git.** `handoff.sh`, `agent-setup.sh`, `consume.py` and `test/run-test.sh` are committed mode 755 (the round-2 entry claimed this; it hadn't happened). `run-test.sh` also runs them through `python3` / `bash` explicitly, so it passes even where execute bits are lost.
- **`consume.py` execs the command** instead of running it as a child. Before, a TERM or HUP sent to the helper (how an MCP client stops a server) killed the helper and left the child running, still holding the credential in its environment; now the command is the process that receives the signal, and the helper keeps no copy of the plaintext once it hands over. A command that can't be run is a clean refusal (exit 127 not found, 126 otherwise), and so is an empty command, a NUL byte, or a credential that isn't valid UTF-8 (before, `--check` crashed on one with a traceback that quoted the character), a blob file that isn't text, and openssl not being installed. `--env` takes only the known credential fields, each once: a typo (`pasword=APP_PASS`) used to add a field no payload had and start the command without the variable. An empty `HANDOFF_PRIVKEY` means the default, and a leading `~` in it is expanded, as an MCP client's JSON `env` passes it literally. Every mapped variable now comes from the payload or not at all: a value already in the caller's environment for a field the payload leaves out is removed, so a planted blob with only a username can't run with the real password beside it.
- **`agent-setup.sh --fingerprint` reads the key the consume side uses.** It read `$HANDOFF_KEY_DIR/handoff-priv.pem` and ignored `$HANDOFF_PRIVKEY`, so during rotation it could report the old key's fingerprint. It now reads a `KEY` argument, else `$HANDOFF_PRIVKEY`, else the same default `consume.py` uses (`$HANDOFF_KEY_DIR` no longer changes which key it reads; an empty value and a leading `~` are treated as `consume.py` treats them), and prints `key file: <path>` on stderr. A new key's path is printed as an absolute path, even for a relative `$HANDOFF_KEY_DIR`. It no longer hides openssl's error, and any other argument prints usage instead of generating a key. `SETUP.md` documents both variables, with exact commands for setup, the fingerprint check and rotation. Rotation now switches one service at a time, so no wrapper pairs a blob with the wrong key.
- **Overclaims corrected.** The threat model said the helper oracle could use a credential "though not revealed", and the README, invariant 3 and SETUP said the agent receives only an exit status. Both were false: the launched command's output reaches the agent, and `-- printenv` prints the credential. The docs now say execute access to the helper is read access to every staged credential. Invariant 8 no longer claims a store write "by anyone" can't swap credentials: a store writer can plant a blob of their own for a label, and that is now listed under "Does not defend against", with signed blobs as the fix.
- **Each label is pinned to its recorded command.** A new hard rule in `SETUP.md`: a label runs only with the commands (its probe and its real use), `--env` mappings and endpoint recorded when it was wired, and changing any of them is a mechanism change. SETUP also has the agent give the user the exact `svc` before they encrypt, and gives the dummy check's exact command. In code, as a partial backstop to that rule, `consume.py` refuses an `--env` target that isn't a plain variable name, one of the well-known variables that change how the command starts (`PATH`, `HOME`, `IFS`, `ENV`, `BASH_ENV`, `LD_*`, `DYLD_*`, `PYTHON*`, `GIT_*`, `NODE_OPTIONS`, the Java options variables and others; mapping a payload field onto `PATH` let the payload choose the binary, and onto `GIT_SSH_COMMAND` the command git runs), and two fields mapped to one variable. No list can name every such variable, which is why the rule, not the list, is the control.
- **The tests check what they claim.** Refusals are matched by exit code and message, with nothing on stdout and no traceback (before, any failure, a crash included, passed as a refusal). The dummy username and password now differ (the vectors are regenerated). Every run checks that no dummy value appears in the helper's own output. New tests cover the exec/TERM behavior, `$HANDOFF_BLOB` and inherited mapped variables being dropped from the command's environment, fingerprint agreement between `agent-setup.sh` and `handoff.sh` (dummy key and a fresh one) and between the two scripts' default key, the 190/191-byte boundary, and 49 refusal checks instead of 3. A mutation run of 47 mutants, each removing or weakening one tested check, kills all 47.
- **Reporting route fixed.** Private vulnerability reporting is now on for the repository, and both `SECURITY.md` files (root and this folder) link its form, name the **Report a vulnerability** button on the **Security and quality** tab, and say a GitHub sign-in is needed. They used to send reporters to the Security → Advisories page (this folder's file to "New draft security advisory"), which only maintainers can use.
- **CI added** for the repository: `run-test.sh`, shellcheck and ruff, on every pull request; plus the PR label workflow the maintainer's other repos use.

## Unreleased — round-2 (cold-read) revision (2026-11-11)

Produced by a cold read of PR #1 by a reviewer seeing the folder for the first time (an AI agent session outside the author's setup; see the README's review note). Findings were graded blockers / substantive / observations; the blockers and substantives are addressed here.

- **B1 — `consume.py` no longer consumes stdin.** It previously read the blob from stdin and then launched the child with that exhausted stdin, which would hand a stdio child (e.g. an MCP server) an immediate EOF on its transport. The blob now arrives by `--blob`, `--blob-file`, or `$HANDOFF_BLOB`; stdin passes to the child untouched, and `test/run-test.sh` has a regression test whose child reads stdin.
- **B2 (script half) — `test/run-test.sh` trap fixed.** Both temp paths are created before the EXIT trap is set; previously an early failure expanded an unassigned variable under `set -u`, aborted the trap, and left the temp key copy behind. (The other half of B2 — the scripts' execute bits — was not actually applied in this revision, though this entry first said it was; see the round-3 entry.)
- **S1 — `agent-setup.sh --fingerprint`** added: recompute an existing key's fingerprint through the shipped tooling, as invariant 6 and SETUP's comparison step require.
- **S2 — `consume.py` never echoes payload content.** The purpose-mismatch error printed the decrypted `svc` value and unknown-field warnings printed raw field names; with unauthenticated payloads, that was a prompt-injection channel into the agent's tool output. Mismatch now names only the caller's label; unknown fields are counted, not named. Non-string-field errors no longer name the field either.
- **S3 — Threat model** now lists the helper-as-decryption-oracle route (execute-access = use-access) and the per-label command-allowlist hardening option.
- **S4 — Four over-claims corrected:** invariant 6's substituted-script wording (a crafted script can lie about its fingerprint), “no plaintext at rest” (swap/core-dump caveat, claim restated exactly), invariant 9's “never sent over a network” (the helper never sends; the consumer's authentication is its normal function), and review provenance (the reviewers are AI agent sessions in the author's setup, not a third-party audit — now stated in the README).
- **S5 — `--env field=NAME`** (repeatable) added to `consume.py`; per-service variable names are configuration, not edits to the script. SETUP's wiring step says so.
- **S6 — argv rule:** SETUP gains a hard rule against credentials on command lines, with the reasoning, and step 6 shows a conforming probe's shape.
- **S7 — `--check` is dummy-only, in both documents.** The docstring no longer advertises it for staged-blob verification; SETUP states the reason (lengths are context-visible).
- **S8 — Separation honesty:** the README now gives the three options when key and store can't be separated, and the threat model covers the unattended-fetch credential explicitly.
- **S9 — Vault section names the mechanisms** (Secure Credentials Store; Sentinel credential surrogation), states the precise gap (username/password declined; no readback path for local processes), and dates the verification (October 2026), with a commitment to revise if the platform ships such a path.
- **S10 — Field-tested vs new:** the README's new Status section separates the daily-use core (October 2026) from the publication-revision additions (`svc` binding, `--check`, `--env`, the refusal set).
- Observations: `handoff.sh` now requires OpenSSL 3 (fails closed on LibreSSL) and validates `svc`/string values at encrypt time (with `jq`); base64 input tolerates wrapped pastes; `--check` with a command is an error rather than silently ignored; the private-key check also verifies ownership; `.gitignore`'s `*priv*` narrowed to `*priv` (it also matched e.g. `docs/privacy.md`); a repo-root `SECURITY.md` added (GitHub surfaces policies from root/`docs`/`.github`, not subfolders); the setup prompt names the repo URL; invariant 10 no longer restates invariant 5; three of the refusal paths are tested (round 3 covers the rest, by exit code and message).

## Unreleased — pre-publication revision (2026-11-11)

Produced by a two-round review (structural review of the documents, then a line-level review of the scripts, with findings reproduced on a separate machine) before this folder's first public commit. Reviewers were AI agent sessions in the author's multi-agent setup; see the round-2 entry and the README's review note.

- **Renamed** from “blind-RSA credential handoff” to **encrypted credential handoff**: “blind RSA” already names a different, standardized technique (blind signatures), and the old name mis-signaled the mechanism.
- **Threat model added** to the README, including what the pattern does not defend against: host trust, the agent-account caveat, the absence of sender authentication, and no forward secrecy under key compromise.
- **Invariants expanded from six to ten**: provenance (stage only user-pasted blobs), purpose binding (`svc`), controlled egress, key confinement, and mandatory (not default) key/ciphertext separation. The setup dummy check now uses `--check` output (field names and lengths) instead of reporting a decrypted value.
- **Rotation split** into routine rotation and compromise response; key rotation alone is no longer presented as a remedy for compromise.
- **consume.py replaces decrypt-example.py**: adds `--label` purpose-binding enforcement, a `--check` mode, unknown-field handling (a payload with no known credential field is refused), non-string field rejection, a missing-key error that names the path, refusal of group/other-readable private keys, clean errors for non-object payloads, and shell-convention exit codes for signal-killed children.
- **handoff.sh fixes**: fingerprint printing now fails closed (a placeholder or damaged embedded key exits 1 instead of printing the SHA-256 of empty input); JSON validation requires exactly one JSON object; neutral `api_key_*` payload examples replace a vendor-shaped token example; `--help` added; stale “blind” wording removed.
- **agent-setup.sh fixes**: openssl stderr no longer suppressed (failures show their cause); `umask 077` set explicitly; a pre-existing key directory's permissions are no longer silently changed; the consume-side `HANDOFF_PRIVKEY` configuration is printed at the end.
- **Platform doctrine corrected**: reviewed reference implementations are the default; agent-written ports are explicitly labeled unreviewed and gated on user review plus the interop test. macOS status stated as expected-but-unreviewed; Windows as no-reference-yet.
- **Interop test added** under `test/` (known-answer vectors) and this changelog and `SECURITY.md` added.
